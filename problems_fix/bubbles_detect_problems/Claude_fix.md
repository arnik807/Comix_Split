## Диагноз (коротко)

Два независимых слоя проблем:
1. **Детектор** — `yolo_manga_int8.onnx` обучен на манге, плохо работает на западных комиксах; плюс resize 640 убивает мелкие баблы
2. **OCR** — PaddleOCR c cyrillic-моделями путает похожие символы при смешанном ru/en тексте (Н→H, и→u и т.д.)

## Приоритет A — Детекция (даст самый быстрый прирост)

### Замена модели: `ogkalu/comic-text-and-bubble-detector`

RT-DETR-v2 r50vd, обучен на **11k изображений** Manga + Webtoon + Manhua + **Western Comic**, три класса: `0=bubble`, `1=text_bubble`, `2=text_free`.

На HuggingFace уже лежит готовый `detector.onnx` (168 MB), ONNX Runtime CPUExecutionProvider, Apache 2.0.

Это прямой ответ на проблему доменного несоответствия — твой `yolo_manga_int8` обучен только на манге, эта модель специально покрывает западные комиксы. Ссылка: `huggingface.co/ogkalu/comic-text-and-bubble-detector`

Тот же автор поддерживает `comic-translate` — приложение автоматического перевода комиксов, которое использует эту модель в production-пайплайне. То есть модель проверена в рабочем инструменте.

### Tiled inference (решает проблему мелких баблов)

Это вторая по важности правка. Панель 1920×1080 сжатая в 640×640 даёт коэффициент ~0.33 — бабл 50×50px становится 16×16px в тензоре, YOLO и RT-DETR его не видят. Решение:

```python
def detect_bubbles_tiled(img, model_session, tile_size=640, overlap=0.2):
    """
    Разбить панель на перекрывающиеся тайлы, запустить детектор на каждом,
    объединить результаты через NMS.
    """
    h, w = img.shape[:2]
    stride = int(tile_size * (1 - overlap))
    all_boxes = []

    for y in range(0, h, stride):
        for x in range(0, w, stride):
            # Вырезать тайл с паддингом до tile_size
            x2 = min(x + tile_size, w)
            y2 = min(y + tile_size, h)
            tile = img[y:y2, x:x2]
            tile_padded = pad_to_square(tile, tile_size)

            boxes = run_detector(model_session, tile_padded)

            # Перевести координаты обратно в систему панели
            for box in boxes:
                box.x1 += x; box.y1 += y
                box.x2 += x; box.y2 += y
                all_boxes.append(box)

    return nms(all_boxes, iou_threshold=0.45)
```

Для типичной панели 1920×1080 это даст 4–6 тайлов 640×640 с 20% перекрытием. Бабл 50×50px будет занимать ~50px в тайле — отлично видим детектору.

### Дополнительно: убрать `_filter_contained` для баблов

В `pipeline._run_yolo()` фильтр вложенных bbox убивает баблы, которые перекрываются (это нормально для комиксов с несколькими облаками). Передавай флаг `skip_containment_filter=True` при вызове bubble-детектора.

## Приоритет B — OCR (фикс «каши» из символов)

### Проблема "не и инг смешиваются"

Это классический симптом когда cyrillic rec-модель и latin rec-модель применяются **последовательно**, и похожие символы (Н/H, И/U, С/C) попадают не в ту модель. PaddleOCR с `lang='ru'` внутри использует только cyrillic rec-весa — при наличии английских букв в баблах результат предсказуемо плохой.

### Решение 1: обновить до PP-OCRv5 (май 2025)

По результатам бенчмарка: EasyOCR выдаёт худший результат, PaddleOCR v4 и v5 дают значительно более высокую точность, Qwen-2.5-VL сопоставим с PaddleOCR но с очень высокой латентностью (0.1–5 сек на изображение). PaddleOCR v5 обеспечивает лучший баланс между точностью, скоростью и покрытием языков.

PP-OCRv5 вышел в мае 2025 с новой модульной архитектурой и интеграцией возможностей больших моделей, поддерживает более 100 языков.

```bash
pip install paddlepaddle paddleocr --upgrade
```

Для смешанного ru/en в баблах — использовать **Latin-based multilingual rec** вместо cyrillic-only:

```python
# Вместо lang='ru' (только кириллица):
ocr = PaddleOCR(use_doc_orientation_classify=False,
                use_textline_orientation=False,
                lang='latin')  # покрывает и латиницу и кириллицу в PP-OCRv5

# Или явная многоязычная конфигурация:
ocr = PaddleOCR(rec_model_name="PP-OCRv5_mobile_rec",
                det_model_name="PP-OCRv5_mobile_det",
                use_angle_cls=False)
```

### Решение 2: два шага OCR внутри одного бабла

Текущий подход — отдать весь кроп бабла в OCR. Лучше:

```
Кроп бабла (+ padding)
  → Paddle det: найти строки текста → list[bbox строки]
  → upscale каждую строку ×4 отдельно (не весь бабл)
  → Paddle rec (без det) на каждой строке
  → concatenate строки по Y-порядку
```

Это то что называется "line-level pipeline" в документе §9 вопрос 6. Разница существенная: вместо детекции текста на фоне 80% белого пространства бабла — детекция строк видит только текст.

### Решение 3: fallback chain

```
Paddle v5 rec → confidence check
  если confidence < 0.6 или len(text) < 2:
    → EasyOCR(['ru', 'en']) на том же кропе
      если всё равно пусто:
        → cloud OCR (Yandex Vision API — бесплатный тир, отличный русский)
```

EasyOCR с `['ru', 'en']` одновременно загружает обе модели и обрабатывает смешанный текст лучше. EasyOCR разработан для работы с вариативными макетами, шрифтами и структурами, что делает его хорошим выбором для извлечения текста из разнородных источников — квитанций, дорожных знаков и форм со смешанным вводом на разных языках.
