# Спецификация модуля Story Analyzer (v2.0)

**Версия документа:** 2.0 (с учётом архитектурного ревью)  
**Дата:** Июнь 2026  
**Статус:** Готово к реализации (MVP)  
**Целевое железо:** AMD Ryzen 5 5600H, 16 GB RAM, AMD Radeon iGPU (Vulkan), Windows 10/11.  
**Стратегия:** Гибридная (Бесплатные API SiliconFlow + Локальные ONNX/CPU инструменты).

---

## 🎯 1. Архитектурные принципы и Модульность

Главное требование v2.0: **Каждый этап должен быть автономным модулем.**  
Это означает, что любой этап можно запустить отдельно, передав ему JSON-файл с результатами предыдущего этапа. Это критически важно для отладки, повторного запуска упавших задач и A/B тестирования моделей.

**Правило взаимодействия этапов:**
`Вход (JSON/Assets) → Обработка → Выход (Обновленный JSON + Новые Assets)`

---

## 📋 2. Детальное описание этапов пайплайна

### STAGE 1: Local Preprocessing (Уже реализовано в ComicSplit)
* **Вход:** Страница комикса (JPG/PNG).
* **Процесс:** Детекция панелей через YOLO, сортировка по порядку чтения, кроп и сохранение в PNG с прозрачным фоном.
* **Выход:** Папка с файлами `panel_XXX.png` и базовый `panels_metadata.json` (содержит `panel_id`, `page`, `image_path`, `bbox`).
* **Статус:** ✅ Готово (`pipeline.py`).

---

### STAGE 2a: Bubble Detection & Local OCR (Исправлено)
* **Вход:** `panels_metadata.json` + папка с `panel_XXX.png`.
* **Процесс:** 
  1. Для каждой панели запускается **существующий** `yolo_manga_int8.onnx` (класс `1 = text_bubble`).
  2. Каждый обнаруженный бабл кропается по своему bbox.
  3. На кроп бабла запускается лёгкий локальный OCR (EasyOCR или классический PaddleOCR), так как он отлично работает на изоированном печатном тексте и не требует API.
* **Выход:** `panels_with_ocr.json` (добавлено поле `"ocr": {"bubbles": [{"text": "...", "bbox": [...]}]}`).
* **Преимущество:** 100% локально, бесплатно, ~0.5 сек на бабл, точная атрибуция текста.

#### 📚 Реестр моделей Stage 2a
| Модель | Ссылка | Описание и роль | Оценка под железо |
| :--- |--- | :--- | :--- |
| **YOLO Manga INT8** | [HF: leoxs22/manga-panel-detector](https://huggingface.co/leoxs22/manga-panel-detector-yolo26n) | **Роль:** Детекция баблов (класс 1). Уже есть в проекте. | ⭐⭐⭐ (ONNX CPU, ~300мс) |
| **EasyOCR** | [GitHub: JaidedAI/EasyOCR](https://github.com/JaidedAI/EasyOCR) | **Роль:** Распознавание текста внутри кропнутого бабла. | ⭐⭐⭐ (CPU, ~200мс на кроп) |

---

### STAGE 2b: Visual Captioning (Критически новый этап)
* **Вход:** `panels_with_ocr.json` + папка с `panel_XXX.png`.
* **Процесс:** Каждая панель (или её уменьшенная копия, например 512x512) отправляется в VLM-модель с промптом: *"Describe the visual action, characters, expressions, and setting in this comic panel in 1-2 sentences. Ignore text."*
* **Выход:** `panels_with_captions.json` (добавлено поле `"visual_caption": "..."`).
* **Зачем это нужно:** Без этого LLM на Stage 4 не узнает, что герой достал меч или сменил локацию, если об этом не сказано в тексте.

#### 📚 Реестр моделей Stage 2b

---

### STAGE 3: Translation (Опционально)
* **Вход:** `panels_with_captions.json`.
* **Процесс:** Если исходный текст не на русском, он отправляется на перевод. Переводятся и реплики, и (опционально) визуальные описания для лучшего контекста.
* **Выход:** `panels_translated.json` (добавлено поле `"text_ru": "..."`).

---

### STAGE 4: Story Understanding
* **Вход:** `panels_translated.json` (или `panels_with_captions.json`).
* **Процесс:** Формируется единый промпт, содержащий **и текст, и визуальное описание** для каждой панели. Модель анализирует поток данных и выявляет: персонажей, их роли, ключевые события, эмоциональный тон и связи между панелями.
* **Выход:** `story_analysis.json` (структурированный JSON с персонажами, саммари и ключевыми событиями).

#### 📚 Реестр моделей Stage 4
| Модель | Ссылка | Описание и роль | Оценка под железо |
| :--- |--- | :--- | :--- |

| **Qwen3.5-122B-A10B** | [SF: Qwen/Qwen3.5-122B-A10B](https://cloud.siliconflow.cn/models) | **Роль:** Глубокий анализ (QUALITY). MoE-архитектура, 256K контекст. | ⭐⭐⭐⭐ (API, ~$0.04 за комикс, отличное качество). |

---

### STAGE 5: Script Generation
* **Вход:** `story_analysis.json` + `panels_translated.json`.
* **Процесс:** Follow-up запрос к той же модели, что и в Stage 4. Задача: превратить анализ в покадровый сценарий для видео. Модель назначает реплики персонажам, добавляет текст рассказчика (нарратора) и дает *оценочную* длительность сцены.
* **Выход:** `video_script.json` (содержит `scenes`, `narrator_text`, `dialogues`, `estimated_duration`).

#### 📚 Реестр моделей Stage 5
* Используется та же модель, что и в **Stage 4**, для сохранения контекста и стиля.

---

### STAGE 6: Voice Synthesis (TTS)
* **Вход:** `video_script.json`.
* **Процесс:** Для каждой реплики и текста нарратора генерируется аудиофайл. Скрипт сохраняет файлы с именами, привязанными к `scene_id` и `character`.
* **Выход:** Папка `audio/` с файлами `.mp3` и обновленный `video_script_with_audio.json` (где добавлены реальные пути к файлам).

#### 📚 Реестр моделей Stage 6
| Модель | Ссылка | Описание и роль | Оценка под железо |
| :--- |--- | :--- | :--- |
| **Edge TTS** (Local/Cloud) | [GitHub: rany2/edge-tts](https://github.com/rany2/edge-tts) | **Роль:** Основной бесплатный TTS. Использует API Microsoft Edge. Отличные русские голоса (Dmitry, Svetlana). | ⭐⭐⭐ (Бесплатно, быстро, не грузит RAM, требует интернет). |
| **CosyVoice2-0.5B** (Cloud) | [SF: FunAudioLLM/CosyVoice2-0.5B](https://cloud.siliconflow.cn/models) | **Роль:** TTS с эмоциями и клонированием голоса (QUALITY). | ⭐⭐⭐⭐ (API, ~$0.05 за комикс, 150ms latency). |

---

### STAGE 7: Timing-Aware A/V Assembly (Исправлено)
* **Вход:** `video_script_with_audio.json` + папка `panels/` + папка `audio/`.
* **Процесс (Критическое исправление):**
  1. Скрипт **игнорирует** `estimated_duration` из LLM.
  2. С помощью `pydub` или `ffprobe` измеряется **реальная длина** аудиофайла нарратора и диалогов для каждой сцены.
  3. Длительность показа панели рассчитывается как: `длина_аудио_нарратора + сумма_длин_аудио_диалогов + 0.5с (переход)`.
  4. Вызывается существующий `anim_pipeline.py` (например, с `mode: opencv_zoom` или `depthflow`), которому передается рассчитанная точная длительность (`--duration`).
  5. FFmpeg микширует аудио и видео, добавляя crossfade между сценами.
* **Выход:** `final_video.mp4` и `storyboard.mp4`.

#### 📚 Реестр инструментов Stage 7
| Инструмент | Ссылка | Описание и роль |
| :--- | :--- |
| **PyDub / FFprobe** | [GitHub: jiaaro/pydub](https://github.com/jiaaro/pydub) | **Роль:** Точное измерение длительности `.mp3` файлов в миллисекундах. |
| **Anim Pipeline** | (Внутренний `anim_pipeline.py`) | **Роль:** Генерация видео-клипа из PNG с заданной длительностью. |
| **FFmpeg** | [ffmpeg.org](https://ffmpeg.org/) | **Роль:** Финальный конкат (сборка) видео и аудио дорожек. |

## 🔗 3. Примеры JSON-схем (Контракты между этапами)

Чтобы обеспечить модульность, этапы общаются через строгие JSON-форматы.

**Выход Stage 2b (`panels_with_captions.json`):**
```json
{
  "panels": [
    {
      "panel_id": "001",
      "image_path": "panels/001.png",
      "ocr": {
        "bubbles": [
          {"text": "We must leave now!", "bbox": [10, 20, 100, 50]}
        ]
      },
      "visual_caption": "A man in a trench coat looks nervously over his shoulder in a dark, rainy alley."
    }
  ]
}
```

**Выход Stage 5 (`video_script.json`):**
```json
{
  "title": "The Escape",
  "scenes": [
    {
      "scene_id": 1,
      "panel_ids": ["001", "002"],
      "narrator": "В темном переулке герой осознал опасность.",
      "dialogues": [
        {"character": "hero", "text": "Мы должны уйти прямо сейчас!", "emotion": "urgent"}
      ],
      "estimated_duration": 5.0 
    }
  ]
}
```

## 🛠 4. План реализации (Модульный подход)

Разработка ведется поэтапно. Каждый этап сопровождается CLI-скриптом для автономного тестирования.

* **Неделя 1: Фундамент (Stage 2a + 2b)**
  * [ ] Написать скрипт `stage_2a_ocr.py`: YOLO manga (class 1) → crop → EasyOCR.
  * [ ] Написать скрипт `stage_2b_caption.py`: Интеграция Florence-2 (ONNX) или запрос к Qwen2.5-VL-3B API.
  * [ ] *Тест:* Прогнать 10 панелей, убедиться, что JSON содержит и текст, и описание картинки.

* **Неделя 2: Мозг (Stage 3 + 4 + 5)**
  * [ ] Написать `stage_4_5_story_and_script.py`: Отправка агрегированного JSON в Qwen2.5-7B (или 122B) с промптом, требующим JSON-ответа.
  * [ ] Реализовать парсинг и валидацию ответа (библиотека `pydantic` или `jsonschema`).
  * [ ] *Тест:* Убедиться, что модель не выдумывает персонажей, которых нет в `visual_caption`.

* **Неделя 3: Голос и Сборка (Stage 6 + 7)**
  * [ ] Написать `stage_6_tts.py`: Интеграция `edge-tts` с маппингом персонажей на голоса.
  * [ ] Написать `stage_7_assembler.py`: Чтение длин аудио через `pydub`, расчет таймингов, вызов `anim_pipeline.py` с флагом `--duration`, финальный `ffmpeg concat`.
  * [ ] *Тест:* Получить первый рабочий MP4 из 5 панелей.

* **Неделя 4: Оркестрация и UI**
  * [ ] Написать `pipeline.py` (главный оркестратор), который вызывает этапы последовательно, сохраняя промежуточные JSON.
  * [ ] Добавить вкладку "Story" в существующий Gradio (`main.py`) с выбором пресета (ECONOMY / QUALITY).

## ⚠️ 6. Управление рисками

1. **Rate Limits на бесплатных API:** 
   * *Решение:* Внедрить библиотеку `tenacity` для автоматических повторных попыток (exponential backoff) и ограничить параллельные запросы (Semaphore = 3).
2. **Галлюцинации LLM в Stage 5:** 
   * *Решение:* Жесткий системный промпт: *"Используй ТОЛЬКО имена персонажей и текст из предоставленного JSON. Не выдумывай новые реплики."* + валидация выходной JSON-схемы.
3. **Рассинхрон аудио и видео:** 
   * *Решение:* Полностью отказаться от предсказания времени LLM. Stage 7 обязан измерять реальные файлы `.mp3` перед вызовом FFmpeg.
