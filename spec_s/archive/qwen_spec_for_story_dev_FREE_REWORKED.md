# 📄 Спецификация: Story Analyzer v3.0 (Tabbed UI Architecture)

**Версия:** 3.0  
**Архитектурный принцип:** Human-in-the-Loop (HITL). Каждый этап — это независимая вкладка в интерфейсе (наравне с Split/Upscale/Video), которая принимает JSON от предыдущего этапа, позволяет визуально редактировать данные и сохраняет валидный JSON для следующего этапа.

## 🌐 Глобальные правила для всех вкладок
1. **Кнопки навигации:** Внизу каждой вкладки: `[ ← Назад ]`, `[ 💾 Сохранить и проверить JSON ]`, `[ Далее → ]`.
2. **Валидация:** Кнопка "Сохранить" запускает проверку выходного JSON по строгой схеме (Pydantic/JSON Schema). Если схема нарушена, подсвечиваются проблемные поля, переход блокируется.
3. **Сохранение состояния:** Промежуточные файлы сохраняются в `story_out/stage_2a.json`, `story_out/stage_2b.json` и т.д., позволяя перезапустить любой этап без потери данных.

## 📑 Детальное описание этапов (Stages)

### STAGE 2a: Bubble Detection & Local OCR
* **Цель:** Точное извлечение текста из баблов с возможностью ручной коррекции.
* **Технологии:** 
  * `yolo_manga_int8.onnx` (класс `1 = text_bubble`) — [Ссылка](https://huggingface.co/leoxs22/manga-panel-detector-yolo26n)
  * `EasyOCR` (локально, CPU) — [Ссылка](https://github.com/JaidedAI/EasyOCR)
* **UI Вкладки "Stage 2a: OCR Корректор":**
  * **Центр:** Canvas (Konva.js), отображающий текущую панель.
  * **Слой:** Поверх изображения рисуются прямоугольники (bbox) вокруг баблов.
  * **Интерактив:** Клик по bbox открывает всплывающее `contentEditable` поле прямо на канвасе с распознанным текстом. Пользователь исправляет ошибки (например, `l` на `I`).
  * **Управление:** Кнопки `[Пропустить бабл]`, `[Добавить бабл вручную]`.
* **Выходной JSON (`panels_2a.json`):**
  ```json
  {
    "panels": [{
      "panel_id": "001",
      "image_path": "panels/001.png",
      "bubbles": [
        {"bbox": [10, 20, 100, 50], "raw_text": "We must leave!", "corrected_text": "We must leave!", "type": "speech"}
      ]
    }]
  }
  ```
* **Критерий успеха:** JSON содержит `corrected_text` для всех баблов, UI позволяет редактировать текст без перезагрузки страницы.

---

### STAGE 2b: Visual Captioning
* **Цель:** Получить текстовое описание визуального ряда (действия, эмоции, фон), которое LLM не увидит в OCR.
* **Технологии:**
  * *Локально:* `Florence-2-large` (ONNX CPU, ~800MB, task: `DETAILED_CAPTION`) — [Ссылка](https://huggingface.co/microsoft/Florence-2-large)
  * *Облако (рекомендуется):* `Qwen/Qwen2.5-VL-3B-Instruct` (SiliconFlow API) — [Ссылка](https://cloud.siliconflow.cn/models)
* **UI Вкладки "Stage 2b: Визальное описание":**
  * **Макет:** Сетка (Grid) миниатюр панелей (например, 300px шириной).
  * **Элементы:** Под каждой миниатюрой — `textarea` с сгенерированным описанием (напр., "Двое героев в доспехах стоят в тёмном коридone, один указывает на выход").
  * **Управление:** Кнопка 🔄 `[Перегенерировать]` (отправляет тот же запрос с уточняющим промптом) и возможность ручного редактирования текста.
* **Выходной JSON (`panels_2b.json`):** Добавляет поле `"visual_caption": "..."` к каждой панели.
* **Критерий успеха:** Сетка отображается без лагов, поле описания редактируемо, кнопка перегенерации обновляет поле без сброса других данных.

---

### STAGE 3: Translation
* **Цель:** Перевод текстов баблов и визуальных описаний на целевой язык.
* **Технологии:** `tencent/Hunyuan-MT-7B` (SiliconFlow API, FREE) — [Ссылка](https://cloud.siliconflow.cn/models)
* **UI Вкладки "Stage 3: Перевод":**
  * **Макет:** Split-view (две колонки). Слева: оригинальный текст (read-only или с пометкой). Справа: переведённый текст в редактируемом поле.
  * **Элементы:** Чекбокс `[x] Не переводить (SFX/звук)` рядом с каждым баблом. Кнопка `[Применить ко всем неотредактированным]`.
* **Выходной JSON (`panels_3.json`):** Добавляет поле `"text_ru": "..."` к баблам и `"caption_ru": "..."` к панелям.
* **Критерий успеха:** Массовый перевод работает, чекбоксы корректно исключают строки из запроса к API, итоговый JSON валиден.

---

### STAGE 4: Story Understanding
* **Цель:** Анализ сюжета, выявление персонажей и связей на основе OCR + Visual Captions.
* **Технологии:** `Qwen/Qwen2.5-7B-Instruct` (FREE) или `Qwen/Qwen3.5-122B-A10B` (QUALITY, ~$0.04/комикс).
* **UI Вкладки "Stage 4: Анализ сюжета":**
  * **Макет:** Две панели. Слева: сворачиваемый список панелей с их `corrected_text` и `visual_caption` (для контекста). Справа: форма с полями, сгенерированными LLM.
  * **Поля формы:** `Список персонажей` (теги), `Краткий сюжет` (textarea), `Ключевые события` (список с возможностью добавить/удалить).
  * **Управление:** Кнопка `[ ✅ Проверить JSON-схему ]`. Подсветка красным, если LLM выдумала персонажа, которого нет в списке панелей.
* **Выходной JSON (`story_analysis.json`):**
  ```json
  {
    "characters": [{"name": "Астерикс", "role": "protagonist", "description": "Галл в крылат头盔е"}],
    "plot_summary": "...",
    "key_events": ["...", "..."],
    "emotional_t Overall_tone": "..."
  }
  ```
* **Критерий успеха:** LLM возвращает валидный JSON, UI позволяет вручную добавить/удалить персонажа, валидатор не пропускает пустые обязательные поля.

---

### STAGE 5: Script Generation
* **Цель:** Преобразование анализа в покадровый сценарий для видео.
* **Технологии:** Та же модель, что в Stage 4 (Follow-up prompt).
* **UI Вкладки "Stage 5: Сценарий":**
  * **Макет:** Список "Сцен" (Cards). Каждая сцена привязана к диапазону `panel_ids`.
  * **Элементы сцены:** 
    * `Текст рассказчика` (textarea).
    * `Диалоги`: Динамический список. В каждой строке: Выпадающий список (Персонаж), Поле (Текст реплики), Выпадающий список (Эмоция: neutral, angry, whisper). Кнопки `[+ Добавить реплику]`, `[🗑 Удалить]`.
    * `Оценочная длительность` (число, сек).
* **Выходной JSON (`video_script.json`):** Структурированный массив сцен с нарратором и диалогами.
* **Критерий успеха:** Возможность динамически добавлять/удалять строки диалогов в UI, итоговый JSON строго соответствует ожидаемой схеме сценария.

---

### STAGE 6: Voice Synthesis (TTS)
* **Цель:** Генерация аудиофайлов для каждой реплики с возможностью предпрослушивания.
* **Технологии:** 
  * *Основной:* `Edge TTS` (Бесплатно, быстро, Microsoft Neural voices) — [Ссылка](https://github.com/rany2/edge-tts)
  * *Альтернатива:* `FunAudioLLM/CosyVoice2-0.5B` (API или локальный ONNX).
* **UI Вкладки "Stage 6: Мини-студия озвучки":**
  * **Макет:** Таблица строк сценария.
  * **Элементы строки:** Текст реплики (с поддержкой простых тегов, напр. `[пауза 0.5с]`), Выпадающий список `Голос` (напр., `ru-RU-DmitryNeural`), Кнопка `[ ▶️ Прослушать ]`, Статус генерации.
  * **Блок "Клонирование голоса" (если CosyVoice):** Поле загрузки `.wav` (3 сек), кнопка `[Сохранить как пресет]`, появление нового голоса в выпадающем списке.
* **Выходной JSON (`video_script_audio.json`):** Добавляет к каждой реплике `"audio_file_path": "story_out/audio/sc01_p01_hero.wav"` и `"actual_duration_ms": 2450`.
* **Критерий успеха:** Аудио генерируется и проигрывается в браузере без перезагрузки, путь к файлу корректно записывается в JSON.

---

### STAGE 7: Timing-Aware A/V Assembly & NLE Export
* **Цель:** Финальная сборка видео ИЛИ экспорт проекта для профессионального монтажа.
* **Технологии:** `PyDub` (измерение длины аудио), существующий `anim_pipeline.py`, генератор `FCPXML`.
* **UI Вкладки "Stage 7: Финальная сборка":**
  * **Выбор режима:** Radio buttons: `[ 🎬 Авто-рендер MP4 ]` или `[ 🎞 Экспорт в видеоредактор (NLE) ]`.
  * **Если NLE:** Выпадающий список: `Final Cut Pro / DaVinci Resolve / Adobe Premiere` (все они поддерживают импорт FCPXML).
  * **Элементы:** Прогресс-бар, лог консоли, кнопка `[ 🚀 Запустить сборку ]`.
* **Логика NLE Экспорта:**
  1. Скрипт создаёт папку `NLE_Assets/`.
  2. Копирует туда все панели (переименовывая в `sc01_p01.png`), все аудиофайлы (`sc01_narrator.wav`, `sc01_hero.wav`).
  3. Генерирует файл `project.fcpxml`, где таймлайн жёстко привязан к `actual_duration_ms` из Stage 6.
* **Выход:** `final_video.mp4` ИЛИ папка `NLE_Assets/` + `project.fcpxml`.
* **Критерий успеха:** Сгенерированный FCPXML успешно импортируется в DaVinci Resolve, все клипы (видео и аудио) лежат на таймлайне с правильными длительностями и без "офлайн" медиа.

# 🗺️ Part 2: Mini-Roadmaps & Implementation Prompts

Для поэтапной разработки. Каждый этап можно давать как промпт мне или другому разработчику.

### 🛠️ Roadmap Stage 2a & 2b (Фундамент)
* **Backend:** Написать скрипт, который берёт `panel.png`, прогоняет через YOLO (class 1), кропает баблы, отдаёт в EasyOCR. Затем отдельный вызов к Florence-2/Qwen-VL для caption.
* **Frontend:** Реализовать Konva-канвас с отрисовкой bbox и `contentEditable` поверх них. Реализовать Grid-виджет для Stage 2b.
* **Success Criteria:** Загрузка 5 панелей → получение `panels_2b.json` с корректными bbox, исправленным текстом и визуальными описаниями.
* **Промпт для реализации:** *"Создай backend-эндпоинт `/api/story/stage_2a/process`, который принимает путь к папке панелей, использует `yolo_manga_int8.onnx` для поиска class 1, кропает их и распознаёт через EasyOCR. Верни JSON с bbox и текстом. На frontend (Konva) сделай так, чтобы по клику на bbox текст можно было редактировать inline."*

### 🛠️ Roadmap Stage 3 & 4 (Смысловая обработка)
* **Backend:** Интеграция Hunyuan-MT-7B API. Интеграция Qwen2.5-7B API с промптом, который принимает JSON из Stage 2b и возвращает строго валидный JSON анализа.
* **Frontend:** Split-view для перевода. Форма с динамическими списками для Stage 4. Кнопка валидации JSON-схемы (через библиотеку `jsonschema` на JS или Pydantic на Python).
* **Success Criteria:** Перевод игнорирует помеченные SFX. Анализ сюжета проходит валидацию, не содержит галлюцинаций персонажей.
* **Промпт для реализации:** *"Напиши промпт для Qwen2.5-7B, который принимает список панелей с полями `corrected_text` и `visual_caption`, и возвращает строго типизированный JSON с персонажами и сюжетом. На frontend добавь валидацию этого JSON по схеме перед кнопкой 'Далее'."*

### 🛠️ Roadmap Stage 5 & 6 (Сценарий и Озвучка)
* **Backend:** Follow-up промпт к Stage 4 для генерации сценария. Эндпоинт `/api/story/stage_6/synthesize`, вызывающий Edge TTS (или CosyVoice), сохраняющий `.wav` и возвращающий `actual_duration_ms` (через `pydub.AudioSegment`).
* **Frontend:** Таблица сценария. Выпадающие списки голосов. Кнопка "Прослушать", которая запрашивает у backend сгенерированный blob и проигрывает его в `<audio>` теге.
* **Success Criteria:** Все реплики озвучены, длительности измерены точно, JSON обновлён путями к файлам.
* **Промпт для реализации:** *"Реализуй модуль TTS на базе `edge-tts`. Создай endpoint, который принимает текст и ID голоса, генерирует аудио, сохраняет в `story_out/audio/`, измеряет его длину в мс через pydub и возвращает путь и длительность в frontend."*

### 🛠️ Roadmap Stage 7 (Сборка и NLE Экспорт)
* **Backend:** Скрипт-оркестратор. 1) Чтение `video_script_audio.json`. 2) Вызов `anim_pipeline.py` для каждой сцены с параметром `--duration`, равным `actual_duration_ms`. 3) Генерация FCPXML (можно использовать готовую библиотеку или шаблонизатор Jinja2). 4) Копирование ассетов в `NLE_Assets/`.
* **Frontend:** Простая форма выбора режима и кнопка запуска с отображением лога.
* **Success Criteria:** Импорт `project.fcpxml` в DaVinci Resolve показывает корректный таймлайн с картинками и звуком, синхронизированными по длительности.
* **Промпт для реализации:** *"Напиши Python-скрипт, который читает `video_script_audio.json`, для каждой сцены вызывает существующий `anim_pipeline.py` с точной длительностью аудио, а затем генерирует валидный FCPXML файл и копирует все медиа в папку `NLE_Assets` с плоской структурой имён."*
