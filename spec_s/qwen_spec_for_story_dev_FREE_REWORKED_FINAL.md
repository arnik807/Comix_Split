## 🎯 Преамбула: предпосылки и цель работы

### Что было проанализировано

Для создания данной спецификации были изучены:

1. **Текущее состояние проекта ComicSplit** — рабочая архитектура MVP (Split/Upscale/Video), YOLO INT8 детекторы панелей (comic/manga), MobileSAM, NCNN-апскейл, DepthFlow parallax, FastAPI v1.3, Gradio, Konva-редактор.
2. **Исходная концепция Story Analyzer** — идея превращения ComicSplit из CV-утилиты в систему автоматической адаптации комиксов в видеоконтент (Split → Story → Script → Voice → Video).
3. **Диалог с пользователем о планах развития** — гибридная архитектура (локально + облако), SiliconFlow как основной провайдер для РФ, паттерн абстракции Provider.
4. **Архитектурное ревью от другой модели** — критические замечания: отсутствие этапа визуального описания панелей (Stage 2b), необходимость детектора баблов перед OCR, недооценка сложности синхронизации аудио/видео, rate limits бесплатных моделей.
5. **Итеративные улучшения** — Tabbed UI (7 независимых вкладок), Pipeline/Standalone режимы, JSON-контракты между этапами, антигаллюцинационный чекер, OpenTimelineIO для NLE-экспорта, DSL-макросы для TTS.
6. **Список моделей SiliconFlow** (`models_siliconFlow.txt`) — каталог доступных LLM/VLM/TTS/ASR моделей с ценами и характеристиками.

### Целевая задача

Спроектировать модуль **Story Analyzer**, который:

1. Превращает папку PNG-панелей (результат Stage 1) в **готовое видео с озвучкой** (реплики персонажей + закадровый голос рассказчика).
2. Работает на целевом железе (локально + через бесплатные API SiliconFlow).
3. Предоставляет **профессиональный редакторский интерфейс** на каждом этапе (Human-in-the-Loop).
4. Позволяет **накапливать библиотеку голосов и характеров** между проектами (легаси-механизм).
5. Поддерживает **автономное использование отдельных этапов** (Sandbox) с возможностью импорта результата в пайплайн.
6. Экспортирует проекты в профессиональные видеоредакторы (DaVinci Resolve, Premiere, Final Cut, CapCut).

### Критерии успеха

✅ Каждый этап — независимая вкладка в UI с собственным рабочим пространством  
✅ JSON-контракты между этапами проходят Pydantic-валидацию

✅ Библиотека голосов и характеров персистентна между проектами  
✅ Sandbox-режим позволяет работать с произвольными данными, результат импортируется в пайплайн  
✅ Финальный MP4 синхронизирован по реальной длине аудио (не по LLM-предсказанию)  
✅ Стоимость обработки 100-страничного комикса в ECONOMY-режиме = **$0**

## 🏛 Часть I. Глобальные архитектурные принципы

### 1.1. Группировка вкладок в UI

Чтобы 7 новых вкладок Story Analyzer не перегружали основную навигацию (текущие 3 вкладки: Split / Upscale / Video), применяется **двухуровневая структура**:

```
[ Split ] [ Upscale ] [ Video ] [ 📖 Story Analyzer ▾ ]
                                   ├─ 2a: OCR Корректор
                                   ├─ 2b: Визуальное описание
                                   ├─ 3: Перевод
                                   ├─ 4: Анализ сюжета
                                   ├─ 5: Сценарий
                                   ├─ 6: 🎙 Студия озвучки
                                   ├─ 7: Сборка / NLE-экспорт
                                   └─ 📚 Библиотека голосов  ⭐
```

Dropdown на базе существующего Konva + vanilla JS (без новых зависимостей).

### 1.2. Pipeline vs Sandbox vs Standalone режимы

Каждая вкладка Story Analyzer работает в одном из трёх режимов, переключаемых в шапке вкладки:

| Режим | Поведение | Кнопки |
|---|---|---|
| 🔄 **Pipeline** (по умолчанию) | Читает JSON от предыдущего этапа (`story_out/pipeline/stage_N-1.json`), пишет в `stage_N.json`. Кнопка `[Далее →]` активна. | `[← Назад]` `[💾 Сохранить]` `[Далее →]` |
| 🧪 **Sandbox** (НОВОЕ в v3.3) | Автономная работа с пользовательскими данными. Сохраняет в `story_out/sandbox/[имя_проекта]/`. При успехе — кнопка `[📤 Импортировать в пайплайн как Stage N]`. | `[📥 Загрузить]` `[💾 Сохранить]` `[📤 Импорт → Pipeline]` |
| 📂 **Standalone** | Окончательный экспорт результата без связи с пайплайном. | `[📥 Загрузить]` `[📤 Экспорт]` |

**Принцип Sandbox → Pipeline (НОВОЕ в v3.3):** Если пользователь экспериментировал в Sandbox (например, переводил свой текст через Stage 3 или озвучивал произвольный текст через Stage 6) и результат ему понравился, он может одним нажатием **импортировать результат в пайплайн** как текущий Stage N. Это делает Sandbox полноценным инструментом прототипирования, а не изолированной песочницей.

### 1.3. JSON-контракты + валидация

- Каждый этап пишет **строгую Pydantic-схему**.
- Кнопка `[💾 Сохранить и проверить JSON]` запускает валидацию.
- При нарушении схемы проблемные поля подсвечиваются красным, переход блокируется.
- **Антигаллюцинационный чекер** (Stage 4): сравнивает имена персонажей с упоминаниями в `corrected_text` + `visual_caption`. Помечает `"hallucinated": true` для выдуманных.

### 1.4. API Key Management + Retry

- **Ключи хранятся централизованно** в `config/api_keys.yaml` (в `.gitignore`).
- **UI:** отдельная панель `⚙️ Настройки API` в dropdown Story Analyzer.
- **Индикатор статуса** в шапке каждой вкладки: 🟢 валиден / 🔴 истёк / ⚪ не задан.
- **Retry с exponential backoff** через `tenacity` для всех API-вызовов SiliconFlow:

```python
@retry(
    stop=stop_after_attempt(5),
    wait=wait_exponential(multiplier=1, min=4, max=60),
    retry=retry_if_exception_type(requests.exceptions.HTTPError)
)
def call_siliconflow_api(model: str, messages: list, **kwargs):
    response = requests.post(...)
    if response.status_code == 429:
        raise requests.exceptions.HTTPError("Rate limited")
    response.raise_for_status()
    return response.json()
```

- **`asyncio.Semaphore(3)`** для ограничения параллельных запросов.

**Назначение:** Анализ сюжета, выявление персонажей и связей на основе OCR + Visual Captions.

#### Технологии

| Модель | Ссылка | Роль | Под железо |
|---|---|---|---|

#### UI вкладки "Stage 4: Анализ сюжета"

- **Макет:** Две панели.
  - **Слева:** сворачиваемый список панелей с их `corrected_text` и `visual_caption` (для контекста).
  - **Справа:** форма с полями, сгенерированными LLM.
- **Поля формы:**
  - `Список персонажей` — теги с ролями (protagonist/antagonist/supporting) и флагом `hallucinated`.
  - `Краткий сюжет` (textarea).
  - `Ключевые события` (динамический список с возможностью добавить/удалить).
  - `Общее настроение` (dropdown: tense/humorous/epic/romantic/etc.).
- **Управление:** Кнопка `[✅ Проверить JSON-схему + антигаллюцинация]`.
- **Подсветка:** красным — персонажи, не упоминающиеся в источниках.

#### Антигаллюцинационный чекер (реализация)

```python
def check_hallucinations(story: Dict, panels: List[Dict]) -> List[str]:
    """Возвращает список имён персонажей, которые есть в story,
    но не упоминаются ни в corrected_text, ни в visual_caption."""
    source_text = " ".join(
        p.get("visual_caption", "") + " " + 
        " ".join(b.get("corrected_text", "") for b in p.get("bubbles", []))
        for p in panels
    ).lower()
    
    hallucinated = []
    for char in story.get("characters", []):
        if char["name"].lower() not in source_text:
            hallucinated.append(char["name"])
    return hallucinated
```

#### JSON-схема выхода (`stage_4_analysis.json`)

```json
{
  "characters": [
    {"name": "Астерикс", "role": "protagonist", "description": "...", "hallucinated": false}
  ],
  "plot_summary": "...",
  "key_events": ["..."],
  "emotional_tone": "tense",
  "setting": "..."
}
```

#### Критерий успеха
- ✅ LLM возвращает валидный JSON.
- ✅ Антигаллюцинатор находит выдуманных персонажей.
- ✅ Можно вручную добавить/удалить персонажа.
- ✅ Промпт содержит **и текст, и visual_caption** — модель не работает вслепую.

### 🎙 STAGE 6: Voice Synthesis Studio ⭐

**Назначение:** Генерация аудиофайлов для каждой реплики с профессиональным контролем интонаций через DSL-макросы, AI-волшебник и **глобальную библиотеку голосов и характеров**.

Это самый богатый по функционалу этап — мини-студия озвучки.

#### 6.1. Основные TTS-технологии

| Модель | Ссылка | Роль | Под железо |
|---|---|---|---|
| **Edge TTS** (основной) | [GitHub: rany2/edge-tts](https://github.com/rany2/edge-tts) | Бесплатный TTS, Microsoft Neural, отличные русские голоса | ⭐⭐⭐ Бесплатно, требует интернет |
| **CosyVoice2-0.5B** (API) | [SF: FunAudioLLM/CosyVoice2-0.5B](https://cloud.siliconflow.cn/models) | TTS с эмоциями и клонированием голоса | ⭐⭐⭐⭐ API, ~$0.05/комикс |
| **MOSS-TTSD-v0.5** (API) | [SF: fnlp/MOSS-TTSD-v0.5](https://cloud.siliconflow.cn/models) | Диалоги двух персонажей одновременно, zero-shot клонирование | ⭐⭐⭐ API |

⚠️ **Локальный ONNX CosyVoice2 удалён из спеки** — требует PyTorch + ~8 GB RAM, что критично на 16 GB. **Только API SiliconFlow.**

#### 6.2. DSL-макросы с выделением и оборачиванием

Простой язык разметки, который **парсится в Python** перед отправкой в Edge TTS и транслируется в SSML.

| Макрос в DSL | SSML-результат | Кнопка тулбара |
|---|---|---|
| `[pause:0.5s]` | `<break time="500ms"/>` | ⏸ Пауза 0.5с |
| `[pause:1.0s]` | `<break time="1000ms"/>` | ⏸ Пауза 1.0с |
| `{whisper}...{/whisper}` | `<prosody volume="x-soft" rate="slow">` | 🤫 Шёпот |
| `{shout}...{/shout}` | `<prosody rate="fast" pitch="+20%">` | 📢 Крик |
| `{sad}...{/sad}` | `<prosody rate="slow" pitch="-10%">` | 😢 Грусть |
| `{angry}...{/angry}` | `<prosody rate="fast" pitch="+15%">` | 😡 Зло |
| `{happy}...{/happy}` | `<prosody rate="medium" pitch="+5%">` | 😊 Радость |
| `{emphasis}...{/emphasis}` | `<emphasis level="strong">` | **B** Акцент |

**Ключевая механика:**
1. Пользователь **выделяет текст мышью** в textarea (например, "беги отсюда").
2. Нажимает кнопку тулбара (например, `[ 📢 Крик ]`).
3. JavaScript получает `window.getSelection()` → оборачивает выделение в `{shout}беги отсюда{/shout}`.
4. Textarea обновляется.

**Пример итоговой строки:**
```
Подожди... [pause:0.5s] {whisper}ты слышишь это?{/whisper} {shout}БЕГИ!{/shout}
```

**Парсер** (`utils/dsl_parser.py`):
- Находит `[pause:Xs]` → заменяет на `<break time="Xms"/>`.
- Находит `{emotion}...{/emotion}` → заменяет на соответствующий `<prosody>` или `<emphasis>`.
- Экранирует XML-символы в обычном тексте.
- Валидирует вложенность (нельзя `{shout}{whisper}...{/shout}{/whisper}`).

#### 6.3. Тулбар над textarea

```
[ 🤫 Шёпот ] [ 📢 Крик ] [ 😢 Грусть ] [ 😡 Зло ] [ 😊 Радость ] [ B Акцент ] [ ⏸ 0.5с ] [ ⏸ 1с ] | [ ✨ AI-помощник ▾ ]
```

Если ничего не выделено — кнопка вставляет пустой wrapper в позицию курсора (для последующего ввода внутри).

**Опционально:** CodeMirror-обёртка textarea с подсветкой `{...}` и `[pause:Xs]` разными цветами.

1. Пользователь вводит описание: *"Он нервничает, говорит тихо, оглядываясь"*.

### 🎯 STAGE 7: Timing-Aware A/V Assembly + NLE Export

**Назначение:** Финальная сборка MP4 **ИЛИ** экспорт проекта для профессионального видеоредактора.

#### Технологии

| Инструмент | Ссылка | Роль |
|---|---|---|
| **PyDub** | [GitHub: jiaaro/pydub](https://github.com/jiaaro/pydub) | Точное измерение длительности `.mp3` в миллисекундах |
| **OpenTimelineIO** | [GitHub: AcademySoftwareFoundation/OpenTimelineIO](https://github.com/AcademySoftwareFoundation/OpenTimelineIO) | Генерация FCPXML/EDL/OTIO |
| **anim_pipeline.py** | Внутренний | Существующий пайплайн анимации (DepthFlow / OpenCV) |
| **ffmpeg** | [ffmpeg.org](https://ffmpeg.org/) | Финальный concat и рендер |

⚠️ **Критическое исправление:** FCPXML генерируется через **OpenTimelineIO**, а не Jinja2-шаблоны. Это гарантирует валидность временных атрибутов `CMTime`, иначе DaVinci Resolve откажет в импорте.

```python
import opentimelineio as otio

timeline = otio.schema.Timeline(name="ComicSplit Project")
track = otio.schema.Track(kind=otio.schema.TrackKind.Video)

for scene in script["scenes"]:
    video_clip = otio.schema.Clip(
        name=f"scene_{scene['scene_id']}",
        media_reference=otio.schema.ExternalReference(
            target_url=f"assets/sc{scene['scene_id']:02d}.mp4"
        ),
        source_range=otio.opentime.TimeRange(
            duration=otio.opentime.from_seconds(scene["actual_duration"])
        )
    )
    track.append(video_clip)

timeline.tracks.append(track)

# Экспорт в три формата одной строкой:
otio.adapters.write_to_file(timeline, "project.fcpxml", adapter_name="fcp_xml")
otio.adapters.write_to_file(timeline, "project.edl", adapter_name="cmx_3600")
otio.adapters.write_to_file(timeline, "project.otio")
```

#### Критическое исправление: реальный тайминг вместо LLM-предсказания

1. Скрипт **игнорирует** `estimated_duration` из Stage 5.
2. С помощью **PyDub** измеряется **реальная длина** аудиофайлов нарратора и диалогов для каждой сцены.
3. Длительность показа панели рассчитывается как: `длина_аудио_нарратора + сумма_длин_аудио_диалогов + 0.5с (переход)`.
4. Вызывается существующий `anim_pipeline.py` с рассчитанной точной длительностью.
5. FFmpeg микширует аудио и видео, добавляя crossfade между сценами.

#### UI вкладки "Stage 7: Финальная сборка"

- **Выбор режима:** Radio buttons:
  - `[🎬 Авто-рендер MP4]` — прямая сборка через `anim_pipeline.py`.
  - `[🎞 Экспорт в NLE]` — генерация проекта для внешнего редактора.
  - `[📋 Только сценарий + аудио]` — без видео, для ручной сборки.
- **Если NLE:**
  - Dropdown: `DaVinci Resolve` / `Adobe Premiere` / `Final Cut Pro` / `CapCut`.
  - Чекбоксы: ☑ Копировать ассеты, ☑ Генерировать EDL-дубликат, ☑ Включить субтитры (SRT).
- **Элементы:** Прогресс-бар, лог консоли, кнопка `[🚀 Запустить сборку]`.

#### Логика NLE-экспорта

1. Создание папки `story_out/pipeline/nle_project/`.
2. Копирование всех панелей (переименование в `sc01_p01.png`).
3. Копирование всех аудиофайлов (`sc01_narrator.wav`, `sc01_hero.wav`).
4. Генерация `project.fcpxml` через OpenTimelineIO.
5. Опционально: генерация `.srt` субтитров.

#### Критерий успеха
- ✅ Сгенерированный FCPXML успешно импортируется в DaVinci Resolve.
- ✅ Все клипы лежат на таймлайне с правильными длительностями.
- ✅ Нет "офлайн" медиа — все ассеты скопированы.
- ✅ Синхронизация аудио и видео основана на реальной длине MP3, а не LLM-предсказании.

## 🧪 Часть IV. Sandbox → Pipeline импорт (НОВОЕ в v3.3)

### 4.1. Проблема

В v3.2 Standalone-режим позволял работать с произвольными данными, но результат оставался изолированным. Пользователь не мог взять, например, понравившийся перевод из Sandbox и использовать его в реальном пайплайне.

### 4.2. Решение: трёхрежимная работа каждой вкладки

Каждая вкладка Story Analyzer имеет три режима в шапке:

1. **🔄 Pipeline** — стандартная работа в последовательности этапов.
2. **🧪 Sandbox** — автономная работа с произвольными данными, с возможностью последующего импорта.
3. **📂 Standalone** — окончательный экспорт без связи с пайплайном.

### 4.3. Логика Sandbox

1. Пользователь выбирает режим `🧪 Sandbox` в шапке вкладки.
2. Вводит имя Sandbox-проекта (например, `test_voice_clone`).
3. Загружает свои данные (произвольный текст, свои изображения, свои аудио).
4. Работает с инструментами вкладки (например, экспериментирует с AI-волшебником в Stage 6).
5. Все результаты сохраняются в `story_out/sandbox/test_voice_clone/`.
6. Если результат понравился — нажимает `[📤 Импортировать в пайплайн как Stage N]`.

### 4.4. Механика импорта

При нажатии `[📤 Импортировать в пайплайн как Stage N]`:

1. Появляется модальное окно с выбором:
